# Plan 18: Switch Vendor Support

> **Phase:** 5 · **Depends on:** 13 · **Status:** Partial (vendor-private OIDs wait for MIBs or fixtures, K-25)

## Goal
Add safe switch support across common vendors.

## Current Source / Reference
Current switch configs include D-Link, Cisco, Juniper, DCN, Raisecom, Eltex, Edgecore, HP/Aruba, TP-Link, UBNT, Arista, Dell, Alcatel, and Allied Telesis.

## Target Design
Switch polling uses common modules with vendor capability flags.
Stack and principles: see [00-overview](00-overview.md#target-architecture).

## Implementation Steps
- Support system, interfaces, counters, errors, LLDP, VLAN summary, SFP optical, and RMON where available.
- Hide unsupported modules.
- Keep FDB disabled by default unless explicitly configured.
- A capability table per vendor decides which modules the UI shows.
- FDB stays disabled unless explicitly configured and bounded.
- Fixtures for each vendor listed in the plan.

## Database/API Impact
Store switch counters/errors/status in normalized interface history tables.

## Frontend Impact
Switch detail page adapts to capabilities.

## Security / Access Rules
Switch actions require switch permissions and device scope.

## Acceptance Checks
- Each switch vendor has safe basic polling.
- Unsupported modules hidden.
- Full FDB disabled unless explicitly configured.
- Unsupported modules are hidden.
- No vendor profile enables a full FDB walk by default.

## Hardware sign-off
Basic polling of each switch vendor within the rate budget. **Not verified against a device.** See [the policy](safety-and-verification-policy.md#4-hardware-sign-off-is-a-separate-explicit-step).

## Risks
- Full table polling on access switches can cause device load.

## Definition of Done
Fixture tests pass for every vendor.

## Rollback
Per-vendor kill switch.

## Implementation notes (2026-10-01)

Nothing here contacted a device. The legacy model files were exported read-only from `origin/main`
(`git archive origin/main vendor/meklis/switcher-core/configs/models`), not merged.

**Safe basic polling for every vendor** rests on standards, not vendor MIBs: `system_basic` and `interface_basic`
(RFC 1213, active since Plan 6) cover identity, link status, counters and the error and discard counters for any
switch. Plan 18 adds two vendor-neutral profiles in `app/registry/switch_standard_oids.py`, both re-derived from the
MIB files in `BDCOM_MIBS/`:

- `rmon_errors`: RMON Ethernet error counters (drop events, CRC/alignment, undersize, oversize, fragments, jabbers,
  collisions) plus `etherStatsIndex`, each walk capped at 512 rows;
- `vlan_summary`: VLAN count, highest VLAN id and supported VLANs (GETs at instance `.0`), plus per-VLAN status
  (one walk, capped at 4096 rows).

Both are seeded as **drafts**: they are standards, but walking them across many access switches has a load cost
Plan 18 wants measured against the rate budget first. Only read-only columns are used, which leaves RMON rows keyed by
`etherStatsIndex` alone and the VLAN summary without names (decision D-30, open).

**Capability table** (`app/registry/switch_capability_data.py`, generated by `tools/gen_switch_capabilities.py`). For
each of the 140 legacy switch models (rewrites included), the read capabilities its own `modules:` block names: system,
link status, counters, errors, LLDP, VLAN summary, SFP optical, RMON, resources, temperature, and FDB. The action
modules each model exposes are recorded separately for Plan 38. Every switch in the detection catalogue has an entry.

**What the UI shows** (`app/vendors/switch_capabilities.py`). `visible_modules` lists only what the model has, in
display order, so unsupported modules are hidden rather than shown empty.

**FDB is off by default** and hidden even on models that support it. Turning it on is per device (`FdbPolicy`). It
needs a row cap (at most 4096), a timeout inside the registry's bounds, and the VLANs to read (1 to 4094, at most 32).
An incomplete or out-of-bounds policy is refused with the reason, and FDB stays hidden. A test also checks that no
profile, in code or seeded, touches the full FDB tables (`dot1dTpFdbTable`, `dot1qTpFdbTable`), their columns or
their parents. Plan 13's one-MAC lookup is a single bounded GET and needs no policy.

Legacy types Dell as a router, so Dell falls under Plan 19.

Tests: 48 (`tests/test_switch_standard_profiles.py`, `tests/test_switch_capabilities.py`). 22 mutations checked:
21 caught, and 1 was equivalent, so the redundant check behind it was removed.

Still to do:

- **fixtures for each vendor**, then the hardware sign-off within the rate budget. Not verified against a device.
