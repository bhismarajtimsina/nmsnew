# Plan 20: Events and Alarms

> **Phase:** 6 · **Depends on:** 10, 12 · **Status:** Partial

## Goal
Create normalized events and alarms for CyberSathy-NMS.

## Current Source / Reference
Current events, alarm rules, alertmanager webhook, and notification components exist in PHP components:
`components/Events/Api/GetIncidentsAction.php`, `components/Events/Controllers/EventProcessors/AlertmanagerEventProcessor.php`,
`components/Events/Storage/EventsStorage.php`, and migrations 064, 065, 067, 069.

## Target Design
Events include scope references and drive alarms, dashboards, realtime, and notifications.
Stack and principles: see [00-overview](00-overview.md#target-architecture).

A single `events` table is the design, ported as-is from the legacy `c_events`: an unresolved row *is* the open
alarm, a resolved row is history. There is no separate acknowledged state and no separate alarm-instance table —
the legacy system does not have one either, and `GetIncidentsAction.php`'s own commit message documents this
collapsing 961 open events into 64 real incidents on production data. `events` is a TimescaleDB hypertable on
`occurred_at`; `alarm_rules` (rule definitions, not alarm instances) is an ordinary relational table.

## Implementation Steps
- Add event types: device down, interface down, high errors, high utilization, bad optical signal, ONU offline, ONU LOS, ONU PowerOff, poller failed, trap received.
- Attach device/interface/OLT/PON/ONU/customer/reseller references.
- Generate alarms from event rules.
- Define the alarm lifecycle: open, acknowledged, cleared; flapping suppression; a dedup key; maintenance windows.
- Port the legacy alarm rules from migrations 064 (audience), 065 (interface down), 067 (complete rules) and 069 (outage sees LOS), with one test per rule.
- Keep Prometheus and Alertmanager as the rule engine for metric alarms; store rule definitions in PostgreSQL and generate rule files (D-24). Validate PromQL before saving.
- Estimate event volume per day and size `events_history` from it (Plan 40).
- Every event carries the scope references needed for filtering (device, interface, OLT, PON, ONU, customer, reseller).

## Database/API Impact
Use relational current events plus TimescaleDB event history if volume requires it.

## Frontend Impact
Dashboards and event pages filter by severity, source, vendor, and scope.

## Security / Access Rules
Resellers see only assigned and impacted-context events.

## Acceptance Checks
- Alarm creates event.
- Event scoped by role.
- Reseller only sees assigned customers/ONUs.
- ISP can see OLT uplink/PON/device events.
- Each ported rule has a passing test.
- A flapping interface produces one alarm, not hundreds.
- An event missing scope references is rejected at write time.
- Reseller sees only assigned and impacted-context events.

## Risks
- Missing scope references can leak or hide events.

## Definition of Done
Rules ported with tests; lifecycle and dedup verified; scope references enforced.

## Rollback
Alarm generation can stay on legacy until cutover; both can run in observe mode with notifications off on the new side.

## Implementation notes (2026-09-29)

Built: migration `20260929_0013` (`alarm_rules`, `events` hypertable, compression at 14 days, 2-year retention);
`app/registry/alarm_rule_data.py`, the real 29-row production alarm rule catalogue generated by
`tools/gen_alarm_rule_catalogue.py` from a live export of `c_events_alertmanager_rules`, seeded idempotently
(`_seed_alarm_rules`, `on conflict (legacy_id) do nothing` — an operator's edit to a rule is never reverted by a
re-seed, the same guarantee vendor kill switches already have); `app/alerting/rulefile.py` (Prometheus rule-file
YAML renderer, D-24); `app/alerting/ingest.py` (Alertmanager webhook ingestion, ported from
`AlertmanagerEventProcessor.php`: device resolution by `dev_id`/`host`/`ip`, fingerprint dedup, a 300-second
startup grace period before a `resolved` notification is honored); `app/alerting/incidents.py` (incident grouping,
ported from `GetIncidentsAction.php`: device-down folding, PON-port grouping, interface grouping, alarm-name
fallback, a 200-event-ID cap per incident); scoped repository and routes in `app/repositories/events.py` and
`app/api/events.py` (`POST /webhooks/alertmanager`, `GET /events`, `GET /events/{id}`, `PUT /events/{id}/resolve`,
`GET /incidents`, `GET /alarm-rules`).

`events.ingest` (the webhook's permission) has no legacy equivalent and is deliberately never granted to any role —
see D-28. It is only ever held by an API token minted by an `api_tokens.manage` holder for Alertmanager's
`webhook_config` itself.

Missing from this pass: flapping suppression (an event that resolves and reopens quickly is currently recorded as
two full events, not suppressed), maintenance windows, `events_history` capacity sizing (Plan 40), the trap
(Plan 21) and notification (Plan 29) workers that would also write into `events`.

Tests: 39 new (`test_alarm_rules.py` 9 + 1 re-seed-protection test, `test_alerting_ingest.py` 10, `test_incidents.py`
11, `test_events_api.py` 9, `test_route_guard.py`/`test_catalogue.py` extended), all passing against a real
PostgreSQL/TimescaleDB.
10 mutations checked (dedup bypass, grace-period bypass, device-down-folding disabled, event-ID cap removed,
scope-visibility bypass, `resolve_event`'s own scope guard removed, the webhook's permission requirement removed,
the `events.ingest` service-only exemption removed, the token permission intersection replaced with a union, and
the alarm-rule re-seed made to overwrite an operator's edit) — all caught.

Two real defects found and fixed before anything shipped:
- The `events` hypertable's downgrade converted it into a plain table and renamed it back to `events` instead of
  dropping it, so a full downgrade to base left `events` behind with a foreign key to `devices`, and
  `test_migrations.py`'s down-to-base round trip failed trying to drop `devices`. Fixed: downgrading `events`
  (created by this same migration) just drops it — dropping a hypertable cascades to its chunks and to the
  compression/retention policies attached to it.
- `app/repositories/events.py` passed `scope_all` as a bind parameter that never appeared in the SQL text on the
  unrestricted-user branch (`visible = "true"`), which asyncpg cannot type (`IndeterminateDatatypeError`). Fixed
  to `"($2::boolean or true)"` in all three affected queries.
