# Support API — Documentation

Документация по внутреннему устройству проекта и разработке.

Порядок чтения рекомендуется от простого к сложному:

| № | Документ | Для кого |
|---|----------|----------|
| 1 | [01-getting-started.md](01-getting-started.md) | **С чего начать.** Составные части бэкенда, зависимости, как поднять проект локально. |
| 2 | [02-directory-layout.md](02-directory-layout.md) | **Как ориентироваться.** Полное дерево каталогов с назначением каждого. |
| 3 | [03-architecture.md](03-architecture.md) | **Как это работает внутри.** Архитектура: HTTP/CLI-флоу, компонентная система, DI, RBAC, кэш, event-bus, poller. |
| 4 | [04-creating-component.md](04-creating-component.md) | **Как расширять.** Пошаговое создание нового плагин-компонента: структура файлов, параметры `config.php`, миграции, rules, console-команды, event listeners. |
| 5 | [05-testing.md](05-testing.md) | **Как тестировать.** Два уровня тестов (integration через HTTP + unit через PHPUnit), как запускать, как писать, CI-пример. Тестов в дереве сейчас нет — документ описывает целевой подход, `PonBoxes` в нём иллюстративный. |

| 6 | [06-cache-and-pollers.md](06-cache-and-pollers.md) | **Кэш и опросчики.** Как устроен SWC cache (Memcache), как работают полеры, два пути поступления данных, почему данные могут не попасть в кэш. |

Отдельные тематические заметки:
- `../PROJECT_OVERVIEW.md` — короткий высокоуровневый обзор (что за проект, стек, ключевые решения).
- `../README.md` — установка bare-metal через apt (альтернатива Docker).

## Соглашения

- Все пути относительно корня репозитория (`/opt/support` или где вы склонировали).
- Команды `wca <cmd>` выполняются внутри контейнера `wca` или через обёртку `bin/wca.sh` (на хосте).
- Примеры на PHP 7.4 — union types и named-args недоступны, но поддерживаются nullable (`?T`) и typed properties.
